# 타워 디펜스 — 발전 계획 (Roadmap)

MVP는 오프라인 단일 정적 배포. 순수 sim·저장 인터페이스 이음새를 따라 단계적 확장.

## Phase 0 — MVP (완료)

- 경로형 그리드 TD, 웨이브 생존(엔드리스+점수), 타워 3종(화살/대포/서리) + 적 2종(일반/빠름).
- 골드 경제(처치+웨이브 보너스), 설치·업그레이드, 라이프·게임오버.
- Canvas 렌더, localStorage best 저장(+메모리 폴백).
- GitHub Pages 배포 + 티스토리 iframe.

## Phase 1 — 게임성 / 완성도

- **이동 투사체**: hitscan → 실제 발사체 레이어(연출). 순수 sim은 유지, 렌더/보간만 추가.
- **타워·적 추가**: 공중 적, 보스, 스플릿 적 / 저격·독·번개 타워, 타워 특수능력·타겟 모드 선택(First/Last/Closest/Strongest).
- **연출**: 발사 트레이서, 폭발 파티클, 사거리 미리보기, 사운드(토글), 배속 버튼(1x/2x).
- **밸런스 튜닝**: 헤드리스 sim으로 웨이브별 난이도 곡선 재조정.
- **접근성**: 색약 팔레트, prefers-reduced-motion.

## Phase 2 — 서버 기록 (Supabase)

- `SupabasePersistence`로 교체(게임 코드 무변경).
- **하이스코어 리더보드**(트렌드 핵심): 도달 웨이브·처치 수 순위. 익명 세션 → 소셜 로그인 선택. RLS.
- 치팅 방지: 결정론 리플레이 검증(시드+입력 로그 재생) 또는 서버 시뮬.

## Phase 3 — Next.js 이식

- 순수 sim 그대로, Canvas를 React 컴포넌트로. 공유 OG 이미지, 리더보드 페이지. 티스토리는 iframe 유지.

## Phase 4 — 수익화 (선택)

- 코스메틱(타워 스킨·맵 테마), 광고 제거. 페이투윈 금지.
- **리워드 광고 (한방 폭탄)**: 광고 시청 시 화면 몹을 거의 제거하는 파워업. 광고 호출은 `src/ads.js`의 `createRewardedAd().showRewardedAd()` **어댑터 하나로 분리**돼 있음.
  - **현재(웹)**: 목업(3초 카운트다운 후 성공). 실제 광고 아님을 UI에 명시.
  - **모바일 전환 시**: 게임을 **Capacitor로 래핑** → `showRewardedAd` 내부만 **AdMob(또는 AppLovin/Unity) 리워드 플러그인** 호출로 교체. `applyBomb` 등 게임 로직은 무변경.
  - 여러 게임을 한 앱에 담으면 광고·저장 어댑터를 **공통 셸**로 공유 가능.
  - 정직성: 웹 정적 블로그 임베드엔 실제 리워드 광고가 부적합(정책·iframe·트래픽) → 앱에서만 실연동.

## 기술 부채 / 체크포인트

- 테스트 승격: 규모 커지면 `node:test` → Vitest. 어댑터 Playwright 상시화.
- 성능: 적·투사체 급증 시 공간 분할(그리드 버킷). 현재 hitscan O(towers×enemies)로 충분.
- 맵 다양성: 현재 단일 고정 경로 → 다중 맵/경로 데이터화.

## 원칙

- YAGNI. 엔진 순수성 사수(게임 규칙은 DOM/네트워크/결제 모름). 밸런스는 추측 대신 실측.
